# 038. Hand meeting changes to project-docs

## Context

A client can agree to a feature without moving the delivery date. The weekly decision then exists, but the requirements used to build and accept the work may still describe an earlier scope.

## Decision

At each successful build-meeting lock, match approved changes to the yes answers in held, locked build weeks. Offer a project-docs update for scope changes that still need one. Ask project-docs to cite the week and change ID when it writes the dated change in the PRD. The exact ID on any dated PRD change line is the receipt, including while the document awaits reapproval.

## Consequences

The weekly records keep their existing fields. An owner who postpones a document update sees the outstanding item at a later close. Project-docs prepares the revised requirement and check and the designated approver approves them. Meeting decisions keep their existing effect on the delivery date.
